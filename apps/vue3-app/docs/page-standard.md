# 列表 + 弹窗页面建设规范

适用场景：后台管理类页面，形态为「列表页（查询/表格/分页） + 弹窗表单（新建/编辑）」。

## 1. 页面分层与职责

- `index.vue`：查询、列表、分页、排序、行操作、弹窗开关。
- `ruleDia.vue`（或同类弹窗组件）：表单展示、回填、联动、校验、提交 payload 构造。
- `api.js`：统一维护接口路径与请求函数，页面内禁止写 URL 字符串。

## 2. 字段与接口口径

- 字段命名以后端 DTO 为准，不允许自定义同义字段。
- 页面对象、表单对象、提交 payload 字段保持一致（如 `ruleName`、`status`）。
- `alertCondition` 这类复合字段由前端组装对象后 `JSON.stringify` 传后端。

## 3. 列表页规范（index）

### 3.1 查询与触发

- 筛选项：关键字、状态（可扩展）。
- 触发方式：
  - 条件变更自动查询（建议防抖 300ms）。
  - 点击查询/重置立即查询。
  - 排序变更立即查询。
  - 分页页码/页大小变更立即查询。

### 3.2 请求并发安全

- 使用请求序号（如 `reqSeq`）保证“后发先至”时只接收最新请求结果。
- 旧请求返回时应丢弃，避免覆盖最新列表状态。

### 3.3 表格与交互

- 表格统一设置 `max-height`（如 `600`）并支持内部滚动。
- 长文案列使用 `show-overflow-tooltip`。
- 状态展示统一标签风格（启用/停用）。
- 行操作至少包含：编辑、启用/停用、删除。
- 启用、停用、删除均弹确认框。

## 4. 弹窗页规范（ruleDia）

### 4.1 基础结构

- 分区建议：
  - 基本信息（如规则名称、启用状态）
  - 触发条件（如分组 + 物理机联动）
  - 告警内容（模板、标签、正文）

### 4.2 打开回填流程

打开弹窗时建议固定流程：

1. 加载分组下拉；
2. 根据 `initialData` 回填表单；
3. 按已选分组加载物理机下拉；
4. 加载模板/标签等辅助数据；
5. 清空旧校验状态。

> 若父组件使用 `v-if` 挂载弹窗组件，`watch(modelValue)` 必须使用 `immediate: true`，确保首次打开即可回填。

### 4.3 联动规则

- 分组变更时，清空该行物理机已选值。
- 物理机列表依赖分组请求。
- 动态行支持新增/删除，最少保留 1 行。

### 4.4 校验规范

- 动态字段使用路径校验：
  - `scopes.${index}.groupId`
  - `scopes.${index}.agentIds`
- 必填项至少包括：规则名称、分组、物理机、异常时长、压缩时长、告警内容。

## 5. 数据模型规范

- 当前推荐的 `alertCondition` 结构（以接口为准）：

```json
{
  "ruleGroup": [{ "groupId": "1", "agentId": "1,2,3" }],
  "relation": "OR"
}
```

- 页面内多选可用数组承载（如 `agentIds: string[]`），提交时转换为接口要求字符串（`agentId`）。
- 若需求已确定使用新版结构，应删除旧版兼容分支，保持代码单一模型。

## 6. 缓存与性能建议

- 分组下拉：可做会话级缓存（打开弹窗不重复请求）。
- 物理机下拉：按 `groupId` 缓存，减少重复请求。
- 查询防抖计时器在组件销毁时清理，避免残留定时器触发请求。

## 7. 代码风格与可维护性

- 重复逻辑抽函数（如状态归一化、ID 拆分、摘要生成）。
- 关键流程加简短注释（打开回填链路、payload 构造、排序映射）。
- 统一错误提示：`ElMessage.error(接口错误或兜底文案)`。
- 禁止保留无用兼容逻辑、无用字段、无效样式。

## 8. 验收清单（每个新页面必过）

- [ ] 字段名与接口 DTO 一致。
- [ ] 查询/排序/分页均正确触发接口。
- [ ] 启用/停用/删除均有确认框。
- [ ] 编辑弹窗首次打开即可正确回填。
- [ ] 分组与物理机联动正确。
- [ ] 提交 payload 与 Swagger 示例一致。
- [ ] 无过时兼容逻辑残留（如已明确不兼容旧版）。
- [ ] 表格与弹窗滚动体验正常。
- [ ] Lint 无报错。

## 9. 联调必测 10 项

- [ ] 列表接口参数正确：`current/size/keyword/status/sortField/sortMode` 与后端约定一致。
- [ ] 关键字、状态筛选变更后触发查询（包含清空状态 `X` 的场景）。
- [ ] 排序切换后按后端字段生效，取消排序可恢复默认列表。
- [ ] 新建成功后列表刷新并回到预期页码（通常第一页）。
- [ ] 编辑打开时完整回填：`ruleName/status/ruleGroup/agentId`。
- [ ] 分组切换后物理机下拉联动刷新，旧选中值被清理。
- [ ] `alertCondition` 提交为字符串，内容结构为 `ruleGroup + relation`。
- [ ] 启用/停用/删除确认框可用，取消不调用接口，失败有错误提示。
- [ ] 下拉接口字段映射正确（`groupId/groupName`、`agentId/agentName`）。
- [ ] 异常场景可恢复：接口报错后不崩溃，loading 状态能正确回收。
